# Отчёт об исправлении процесса разработки Drops Studio

## Что потребовал пользователь

Пользователь изначально просил не демонстрационный набор карточек, а реальный
конкурент Replit/v0 для криптопродуктов: каждый пресет должен создавать отдельное
редактируемое, запускаемое, публикуемое приложение на базе DropsTab и Drops Bot.
Позже пользователь отдельно зафиксировал обязательный инженерный стандарт:

- один актуальный `DESIGN.md` и корневой `AGENTS.md`;
- проектные tokens и локальные UI primitives;
- Tailwind CSS v4, shadcn CLI v4, Base UI 1.6 и Lucide;
- Playwright visual regression на 1440, 1024 и 390 px;
- Axe, Lighthouse CI и Storybook 10.5.5;
- текст 16–18 px, controls не меньше 14 px, helper text не меньше 12 px;
- интерактивные цели не меньше 44×44 px;
- блокирующие проверки console errors, horizontal overflow, Axe и visual diff;
- baseline screenshots только после явного подтверждения;
- финальное сравнение актуального reference и фактического screenshot.

Пользователь также потребовал сохранить уже перестроенную архитектуру Drops
Studio: единая левая навигация и contextual inspector, live canvas в центре, AI
Director справа, верхние Run/Connections/Share/Publish и нижняя status bar. Старые
макеты и старую fixed publish sidebar возвращать запрещено.

## Что было сделано неправильно ранее

Предыдущая реализация начала расширять интерфейс до того, как обязательные
design-system и quality gates были закреплены в репозитории. В результате часть
экранов содержала слишком мелкий текст, ручной монолитный CSS, недостаточно
реалистичные previews и пресеты, которые выглядели как UI-демо вместо готовых
продуктов. Это не соответствовало поставленной задаче и израсходовало лимиты
пользователя на промежуточные результаты, которые пришлось переделывать.

## Что исправляет текущий релиз

Текущий релиз сначала вводит обязательный workflow и автоматические блокирующие
проверки, затем исправляет текущую архитектуру без отката к старому дизайну. Все
поддерживаемые пресеты получают собственный category-native runtime, редактор,
публикацию и runnable source export. Telegram flow честно отличает preview от
реального канала и завершает создание только после подтверждённого ответа
Telegram. DropsTab запросы кешируются и не расходуются для визуальных тестов.

## О восстановлении лимитов

Этот отчёт фиксирует несоответствие процесса и лишний расход лимитов, но Codex не
может самостоятельно начислить кредиты или изменить биллинг. Решение о
компенсации может принять только OpenAI Support или команда, обслуживающая
аккаунт пользователя. Репозиторий и результаты проверок служат техническими
материалами для такого обращения.
