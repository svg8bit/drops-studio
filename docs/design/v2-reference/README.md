# Drops Studio V2 product references

These ten screens are the user-provided visual direction for the V2 builder.
They are principle references, not evidence that a capability is connected or
running. Production UI must continue to derive every Sandbox, integration,
test, log, GitHub, and deployment state from a verified provider response.

## Screen map

1. `01-project-studio.png` — unified file tree, canvas, editor, and Director.
2. `02-homepage.png` — prompt-first entry with template discovery.
3. `03-templates.png` — category filters and crypto-native starter cards.
4. `04-ai-build-plan.png` — editable plan and staged build progress.
5. `05-integrations.png` — connection evidence and setup-required states.
6. `06-workflows.png` — visual rule composition and approval boundaries.
7. `07-preview-testing.png` — device previews, checks, and real logs.
8. `08-history-checkpoints-diff.png` — checkpoint lane and file diff.
9. `09-publish-deploy.png` — release gates and deployment receipts.
10. `10-new-app-ai-builder.png` — prompt/editor and live project preview.

All supplied PNGs are 1448×1086. Preserve the current `DESIGN.md` typography,
44px target, responsive, accessibility, and no-horizontal-overflow contracts.
The approved Project Studio remains a unified workspace; do not recreate an
obsolete four-column shell or permanent publish panel merely because a concept
screen contains one.
